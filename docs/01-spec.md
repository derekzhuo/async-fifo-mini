# 01 规格与行为契约：先定义一次正确的读写

异步 FIFO 的作用是跨越两个彼此独立的时钟域传递数据：生产者只在 `wclk` 域写入，消费者只在 `rclk` 域读出。这里的「异步」指两个时钟没有可依赖的固定相位或频率关系，而不是接口不需要时钟。本工程采用典型的双时钟、寄存指针、格雷码同步结构，对应实现见 `rtl/async_fifo.v`。

阅读规格时要始终区分两类信息：数据和写指针由写侧产生，读指针由读侧产生；写侧只能根据同步过来的读指针判断满，读侧只能根据同步过来的写指针判断空。这一限制决定了满空标志天然具有保守性，不能把它们理解成对另一域当前状态的零延迟观察。

## 一、接口信号

RTL 中写使能和读使能的名字是 `winc`、`rinc`，分别对应许多资料里的 `wr_en`、`rd_en`。下文使用源码中的真实名字，避免照抄概念图后无法对应代码。

| 信号 | 方向 | 位宽 | 所属时钟域 | 含义与有效条件 |
|---|---|---:|---|---|
| `wclk` | 输入 | 1 | 写域 | 写指针、写侧同步器和 `wfull` 的时钟，上升沿有效 |
| `wrst_n` | 输入 | 1 | 写域 | 写侧低有效复位；拉低清零写指针、写侧同步寄存器和 `wfull` |
| `winc` | 输入 | 1 | 写域 | 写使能；仅在有效 `wclk` 上升沿且 `wfull=0` 时接收 `wdata` |
| `wdata` | 输入 | `DATA_WIDTH` | 写域 | 待写数据；应在接收写入的时钟沿附近满足建立、保持要求 |
| `wfull` | 输出 | 1 | 写域 | 写满标志；为 1 时写请求被忽略，只能由写域逻辑使用 |
| `rclk` | 输入 | 1 | 读域 | 读指针、读侧同步器和 `rempty` 的时钟，上升沿有效 |
| `rrst_n` | 输入 | 1 | 读域 | 读侧低有效复位；拉低清零读指针、读侧同步寄存器，并置 `rempty=1` |
| `rinc` | 输入 | 1 | 读域 | 读使能；仅在有效 `rclk` 上升沿且 `rempty=0` 时消费当前数据并推进读指针 |
| `rdata` | 输出 | `DATA_WIDTH` | 读域 | 当前读地址对应的存储内容，采用组合读；仅在 `rempty=0` 时有消费意义 |
| `rempty` | 输出 | 1 | 读域 | 读空标志；为 1 时读请求被忽略，只能由读域逻辑使用 |

`wfull` 与 `rempty` 都是寄存输出，不会在一个周期中间随着组合地址变化任意毛刺式翻转。这是好事，但不意味着可以跨域使用：例如，不能让 `rclk` 域的读控制直接依赖 `wfull`。

## 二、参数、深度与容量

模块只暴露两个参数：

```verilog
parameter DATA_WIDTH = 8,
parameter ADDR_WIDTH = 4
```

深度由下面的本地参数确定：

```verilog
localparam DEPTH = 1 << ADDR_WIDTH;
```

因此默认配置是 16 项、每项 8 位，总数据容量为 128 bit。一般关系为：

- 存储项数：`DEPTH = 2^ADDR_WIDTH`；
- 每项位数：`DATA_WIDTH`；
- 数据存储容量：`2^ADDR_WIDTH × DATA_WIDTH` bit；
- 二进制与格雷码指针位宽：`ADDR_WIDTH + 1` bit。

指针多出来的一位用于区分「读写地址相同但队列满」与「读写地址相同且队列空」，不是额外增加一层存储。`mem` 的下标仍然只取低 `ADDR_WIDTH` 位。

**`ADDR_WIDTH` 必须不小于 2，深度必须是 2 的幂。** 后一条由地址自然回绕机制决定；前一条来自当前满判定要对格雷码指针高两位取反，`ADDR_WIDTH=1` 会使切片语义不再符合这套结构。需要非 2 幂深度时，不能只改参数，应重新设计回绕与满空判断。

## 三、正常写入契约

在一次有效写入前，写侧应看到 `wfull=0`，并驱动 `winc=1` 与稳定的 `wdata`。在 `wclk` 上升沿同时发生三件事：

1. 当前 `wbin` 的低 `ADDR_WIDTH` 位选中的存储项写入 `wdata`；
2. 写二进制指针加 1；
3. 写格雷码指针更新为与新二进制指针对应的值。

核心代码是：

```verilog
if (winc && !wfull)
    mem[wbin[ADDR_WIDTH-1:0]] <= wdata;
```

指针计算也显式包含同一个准入条件：

```verilog
wire [ADDR_WIDTH:0] wbin_next = wbin + (winc & ~wfull);
```

所以「写使能」不是无条件接收承诺。若写侧无视 `wfull` 持续拉高 `winc`，FIFO 会忽略新数据，既不覆盖旧数据，也不会事后补写。上游如果需要可靠传输，必须自己实现背压、重试或丢弃统计。

## 四、正常读出契约与读延迟

本工程的存储读是组合赋值：

```verilog
assign rdata = mem[rbin[ADDR_WIDTH-1:0]];
```

当 `rempty=0` 时，当前队首数据已经由当前 `rbin` 指向，并呈现在 `rdata` 上。消费者在某个 `rclk` 上升沿令 `rinc=1`，表示消费该沿之前看到的数据；此沿之后读指针才加 1，`rdata` 随后切到下一项。

因此，从接口协议看：

- **消费动作发生在 `rinc && !rempty` 的读时钟上升沿；**
- **当前数据在该沿之前已经可读，不需要先等一个「读输出寄存器」周期；**
- **读指针推进后，组合输出按新地址变化；**
- **`rempty=1` 时不能消费 `rdata`，即使波形上仍能看到旧值或某次写入的新值。**

这与标准延迟读出模式在队首已有数据时的使用方式一致：看当前 `rdata`，用 `rinc` 确认消费。但它不是 FWFT（First-Word Fall-Through，首字直通）所附带的完整接口语义，也没有 `rd_valid` 这类独立数据有效信号。系统应只根据 `rempty` 判断数据是否有效。

## 五、满、空与保守延迟

`wfull=1` 表示写侧判定不能再接收新项；`rempty=1` 表示读侧判定没有可消费项。两侧都要遵守：

| 状态 | 外部请求 | FIFO 行为 | 外部系统应做什么 |
|---|---|---|---|
| `wfull=1` | `winc=1` | 不写存储、不动写指针 | 背压或记录丢弃，不得假设写入成功 |
| `rempty=1` | `rinc=1` | 不推进读指针 | 停止消费，等待 `rempty=0` |
| `wfull=0` | `winc=1` | 在写时钟沿接收 | 保证数据与使能时序 |
| `rempty=0` | `rinc=1` | 消费当前队首并推进读指针 | 在该沿采样正确的 `rdata` |

由于另一域指针经过两级寄存器同步，标志可能晚于真实事件变化：

- 读侧已经读走数据后，写侧可能仍短暂看到 `wfull=1`，因此晚一点恢复写入；
- 写侧已经写入数据后，读侧可能仍短暂看到 `rempty=1`，因此晚一点开始读出。

这会牺牲少量吞吐响应时间，却不会因「看得太新」而写出界或读出界。不要把这种短暂状态误判为指针损坏。

## 六、复位契约

两个复位彼此独立，低有效，RTL 采用异步置位/清零：

- `wrst_n=0` 清写指针、写侧同步的读指针以及 `wfull`；
- `rrst_n=0` 清读指针、读侧同步的写指针，并令 `rempty=1`；
- 存储数组 `mem` 没有复位，复位只让已有内容在逻辑上不可见，不会逐项清零；
- 两侧都完成复位并稳定运行后，队列为空，读写指针均从 0 开始。

系统初始化时，建议两侧同时处于复位，然后分别在本时钟域同步释放。当前 RTL 没有内置复位释放同步器，不能把「两级格雷码同步器」误当成复位同步器。运行中只复位一侧会改变队列的全局一致性假设，可能遗留、废弃或重复解释数据；若业务需要这种能力，必须在上层定义清空协议并专门验证，不能把它当作普通单域复位使用。

复位错开的具体可观察现象见 `tb/tb_reset_skew.v`：写侧先释放时，数据可以写入，读侧仍保持 `rempty=1`；读侧释放并同步到新写指针后，首数据仍可正常读出。这不等于允许读侧在复位中消费 `rdata`。

## 七、有意不提供的功能

为了保持教学实现足够小，本工程没有加入以下常见商用 FIFO 功能：

| 功能 | 当前行为 | 未加入的原因与替代方式 |
|---|---|---|
| `almost_full` / `almost_empty` | 只有精确满、空标志 | 可编程水位会引入另一域阈值比较和更多验证场景；上层可用独立缓冲策略降低对水位的依赖 |
| FWFT 完整接口 | `rdata` 虽为组合读，但仅以 `rempty` 表示有效性 | 避免把「组合可见」与完整首字直通协议混为一谈；需要 `valid` 时应另行定义 |
| 数据计数器 | 不输出任一域的精确占用量 | 跨域计数只能得到带延迟的估计，容易诱导误用；按满空做流控已足够演示核心机制 |
| 非 2 幂深度 | 不支持 | 自然二进制回绕与格雷码满判定依赖 2 幂深度 |
| 写溢出、读下溢错误输出 | 忽略非法请求，不输出错误脉冲 | 保持接口最小；上游必须遵守满空，验证平台负责把非法行为显式记录下来 |
| 掉电保持或存储清零 | 复位不清 `mem` | 清空指针即可定义逻辑空，逐项复位会阻碍高效存储实现 |
| 内建复位释放同步器 | 由外部系统保证 | 复位策略与具体芯片、时钟和系统初始化流程相关，需按目标环境实现 |

这些省略不是宣称它们不重要，而是把学习焦点集中在跨域指针本身。如果用于真实产品，还应结合目标器件的 CDC 约束、复位策略、形式验证与存储 IP 做完整签核。
