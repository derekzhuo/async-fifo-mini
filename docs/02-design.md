# 02 设计原理：格雷码、多一位指针与满空判定

异步 FIFO 难的不是用一个数组存数据，而是让两个时钟域对「队列里还有多少数据」形成安全判断。写侧知道本地写指针，读侧知道本地读指针，但任何一侧都不能直接采样另一侧正在变化的二进制指针。本工程的解决办法可以概括为四句话：

1. 二进制指针只在本域运算和寻址；
2. 跨域只传格雷码指针；
3. 格雷码指针经过两级触发器同步后再用于比较；
4. 指针比存储地址多一位，用额外相位区分满与空。

下面按这条链路拆解 `rtl/async_fifo.v`。

## 一、为什么二进制指针不能直接跨域

先看一次普通的二进制递增：`0111 → 1000`。四位在同一个源时钟沿发生变化，但物理触发器、走线和接收端采样点不可能完全一致。若目的时钟恰好在变化附近采样，可能看到一些位已更新、另一些位尚未更新，也可能遇到亚稳态。于是一次合法递增可能被读成 `0000`、`1111`、`1001` 等并非源指针曾稳定呈现的组合。

问题不只是「采到旧值还是新值」。单独一位跨域时，采到旧值通常只是慢一点；多位同时跨域时，**不同位来自不同次更新**，拼出来的值可能既非旧指针也非新指针。把这样的值拿去做满空比较，可能让写侧误以为还有空间，或让读侧误以为还有数据，后果是覆盖未读数据或消费无效数据。

有人想用「多等几拍再采样整个二进制总线」解决，仍然不够：等待只能降低亚稳态传播概率，不能保证各位在同一次源更新中保持一致；握手机制虽然可以传多比特数据，却会引入额外协议与延迟，不是本设计采用的指针同步方式。

格雷码解决的是其中一半问题：让相邻计数值只有一位变化。两级同步解决另一半问题：降低单个跨域信号亚稳态继续传播的概率。二者分工不同，缺一不可。

## 二、格雷码为什么适合这里

RTL 用移位异或完成二进制到格雷码转换：

```verilog
wire [ADDR_WIDTH:0] wgray_next = (wbin_next >> 1) ^ wbin_next;
wire [ADDR_WIDTH:0] rgray_next = (rbin_next >> 1) ^ rbin_next;
```

对任一位 `i`，转换公式是 `gray[i] = bin[i+1] ^ bin[i]`，最高位则相当于与补进来的 0 异或，因此保持不变。以 4 位指针为例，二进制 7 到 8 的变化是：

| 数值 | 二进制 | 格雷码 | 格雷码变化位数 |
|---:|---|---|---:|
| 6 | `0110` | `0101` | — |
| 7 | `0111` | `0100` | 1（相对 6） |
| 8 | `1000` | `1100` | 1（相对 7） |
| 9 | `1001` | `1101` | 1（相对 8） |

二进制 `0111 → 1000` 四位全变，格雷码却只是 `0100 → 1100`，只有最高位由 0 变 1。接收端在这个变化附近采样时，理想逻辑结果只能是变化前或变化后的相邻指针，不会拼出一个跨度很大的伪指针。

这并不表示格雷码总线天然免疫亚稳态。变化的那一位仍可能在接收触发器中进入亚稳态，所以后面仍要两级同步；只是其他不变化的位不会同时制造额外的不确定组合。

### 为什么本域仍保留二进制指针

格雷码适合跨域，却不适合直接做数组下标和普通加减。于是模块同时保留：

```verilog
reg [ADDR_WIDTH:0] wbin, wgray, rbin, rgray;
```

`wbin`、`rbin` 用于本地递增、地址切片和回绕；`wgray`、`rgray` 是它们的跨域表示。两边在同一个源时钟沿更新，保证二者始终对应同一个 next 状态，而不是错开一拍：

```verilog
end else begin
    wbin <= wbin_next;
    wgray <= wgray_next;
    if (winc && !wfull)
        mem[wbin[ADDR_WIDTH-1:0]] <= wdata;
end
```

读侧更新方式相同，只是没有存储写操作：

```verilog
end else begin
    rbin <= rbin_next;
    rgray <= rgray_next;
end
```

「由 `wbin_next` 生成 `wgray_next`，再同时寄存」这一点很重要。如果先用旧二进制指针算格雷码，会让两种指针错开，后续比较和地址就可能不一致。

## 三、指针为什么多一位

假设 FIFO 深度为 8，存储地址只需 3 位，读写低三位相等可能对应两种完全不同的情况：

- 读指针追上了写指针，队列空；
- 写指针比读指针多走了整整 8 项，队列满。

只比较三位地址无法区分。给指针增加第 4 位后，低三位仍是存储地址，最高位记录已经绕过地址空间多少次。于是「指针相等」表示同一相位、同一位置，即空；「写指针恰好领先一整圈」则用特定格雷码位型表示满。

源码声明清楚地体现了这一点：

```verilog
reg [ADDR_WIDTH:0] wbin, wgray, rbin, rgray;
```

方括号写成 `ADDR_WIDTH:0`，总宽度就是 `ADDR_WIDTH+1`。但存储寻址只取低位：

```verilog
assign rdata = mem[rbin[ADDR_WIDTH-1:0]];
```

写入也类似：

```verilog
mem[wbin[ADDR_WIDTH-1:0]] <= wdata;
```

下表以深度 8 为例，展示连续写入而暂不读取时指针如何变化。`wbin` 是 4 位，`wgray` 也是 4 位，读指针保持在 `0000 / 0000`：

| 已写项数 | `wbin` | `wgray` | 队列状态 |
|---:|---|---|---|
| 0 | `0000` | `0000` | 空 |
| 1 | `0001` | `0001` | 1 项 |
| 2 | `0010` | `0011` | 2 项 |
| 3 | `0011` | `0010` | 3 项 |
| 4 | `0100` | `0110` | 4 项 |
| 5 | `0101` | `0111` | 5 项 |
| 6 | `0110` | `0101` | 6 项 |
| 7 | `0111` | `0100` | 7 项 |
| 8 | `1000` | `1100` | 满 |

第 8 项写入后，低三位重新回到 `000`，但最高位为 1。正是这个额外相位让「又到低地址」不会被误判成空。

## 四、满判定的「高两位取反」逐位推导

写侧当前收到的同步读格雷码为 `rgray_wsync2`，下一次写格雷码为 `wgray_next`。满判定是：

```verilog
wfull <= (wgray_next == {~rgray_wsync2[ADDR_WIDTH:ADDR_WIDTH-1],
                         rgray_wsync2[ADDR_WIDTH-2:0]});
```

文字描述是：把同步读格雷码的最高两位取反，低位原样保留；若下一个写格雷码等于这个变换值，下一状态就是满。之所以比较 next 值，是要在「最后一次可接受写入完成后」让寄存的 `wfull` 立即变为 1，阻止再下一次写入。

### 用深度 8 的真实位型验证

深度 8 时 `ADDR_WIDTH=3`，指针宽 4 位。读指针为 0：

```text
rgray_wsync2 = 0000
```

取反高两位、保留低两位：

```text
原值：       0 0 0 0
             ↑ ↑ ↑ ↑
高两位取反：  1 1 0 0
结果：       1 1 0 0 = 1100
```

所以满条件为 `wgray_next == 1100`。上表已经给出：写第 8 项后，`wbin_next=1000`，对应 `wgray_next=1100`，于是 `wfull` 置 1。低两位相同表示读写落在同一存储地址；高两位相反表示写侧恰好领先一整圈，而不是与读侧同圈相等。

再看一个不是简单全零的例子。设同步读二进制指针为 3，即 `rbin=0011`，其格雷码为：

```text
rgray_wsync2 = 0010
```

满判定目标是：

```text
{~00, 10} = 1110
```

4 位格雷码 `1110` 对应二进制 `1011`，即十进制 11；11 比 3 恰好多 8。因此这条公式并不只在复位后从零开始写时成立，对任意读指针位置都表达同一个条件：

```text
写指针 - 读指针 = DEPTH
```

### 为什么是「高两位」，不是只反最高位

在普通二进制反射格雷码中，指针完整回绕一圈会让高两位关系同时变化。只反最高位会把另一个非满位置也纳入比较，或者无法正确表达整圈差。这里的结论是建立在当前 Gray 构造方式、2 幂深度和 `ADDR_WIDTH+1` 位指针之上的组合条件，不能抽出来套到任意编码。

也应避免把满条件误解为直接比较 `wbin` 与 `rbin`。跨域总线是格雷码，公式比较的是 `wgray_next` 与同步后的 `rgray_wsync2`；如果改成二进制比较，前面讨论的多位翻转问题就回来了。

## 五、空判定为什么直接比较相等

读侧逻辑短得多：

```verilog
rempty <= (rgray_next == wgray_rsync2);
```

当读指针推进到与同步写指针相同的位置，说明读侧已经追上写侧已发布的数据末尾，下一状态为空。这里不需要位取反，因为空对应「同圈、同位置」，满才对应「相差整圈」。

与满逻辑一样，空也比较 next 值。读出最后一项后，`rgray_next` 追上写指针，`rempty` 在该读时钟沿后变为 1，防止下一次无效读取。复位时读侧直接执行：

```verilog
if (!rrst_n)
    rempty <= 1;
```

所以队列的初始状态被明确宣布为空，而不依赖未初始化的存储内容。

## 六、两级同步与保守延迟的方向安全性

写域接收读格雷码：

```verilog
always @(posedge wclk or negedge wrst_n) begin
    if (!wrst_n)
        {rgray_wsync2, rgray_wsync1} <= 0;
    else
        {rgray_wsync2, rgray_wsync1} <= {rgray_wsync1, rgray};
end
```

读域接收写格雷码：

```verilog
always @(posedge rclk or negedge rrst_n) begin
    if (!rrst_n)
        {wgray_rsync2, wgray_rsync1} <= 0;
    else
        {wgray_rsync2, wgray_rsync1} <= {wgray_rsync1, wgray};
end
```

每个目的域都有两个串联寄存器。第一级直接面对异步输入，可能发生亚稳态；第二级给第一级留出约一个目的时钟周期的恢复时间，再把信号送给比较逻辑。两级同步显著降低亚稳态传播概率，但不能把概率说成数学上的零。实际芯片还需合适的同步寄存器约束和 CDC 检查。

拼接写法容易看反，以写域为例，非阻塞赋值右侧取旧值：

```text
旧 rgray       → rgray_wsync1 → rgray_wsync2
（跨域输入）     （第一级）       （第二级，供满比较）
```

也就是 `rgray_wsync1` 接收外部 `rgray`，`rgray_wsync2` 接收旧的第一级值。读域方向相反，但结构完全相同。

### 为什么延迟不会把空/满做反

读侧看到的是最多滞后的写指针，因此可能少认为有数据：真实已经有新项，`rempty` 却仍暂时为 1。这是保守空，不会把不存在的项当有效数据。

写侧看到的是滞后的读指针，因此可能少认为有空间：真实已经读走，`wfull` 却仍暂时为 1。这是保守满，不会在空间尚未被确认时覆盖旧数据。

可以用下表记忆：

| 本地判断 | 对端真实事件 | 同步延迟造成的暂时现象 | 安全结果 |
|---|---|---|---|
| 读空 | 写侧刚写入 | `rempty` 多保持一段时间 | 晚读，不读无效项 |
| 写满 | 读侧刚读走 | `wfull` 多保持一段时间 | 晚写，不覆盖有效项 |

这种安全性依赖指针单调向前和 Gray 单比特变化。若任意修改指针、允许非顺序跳变或把多位二进制控制信息搭在同一同步器上，就不再享有同样的推理。

## 七、分侧复位与释放：RTL 做了什么，系统还要做什么

四个时序块都采用类似结构：

```verilog
always @(posedge wclk or negedge wrst_n) begin
    if (!wrst_n)
        wfull <= 0;
    else
        wfull <= (wgray_next == {~rgray_wsync2[ADDR_WIDTH:ADDR_WIDTH-1],
                                 rgray_wsync2[ADDR_WIDTH-2:0]});
end
```

敏感列表里的 `negedge wrst_n` 表示异步复位断言：不必等时钟沿，拉低就复位。写侧清写指针和写域同步器，读侧清读指针和读域同步器；`mem` 不复位。这样的分工让每侧寄存器只由自己的复位和时钟控制，避免多驱动。

**当前代码没有专门实现同步释放。** `wrst_n`、`rrst_n` 从 0 回到 1 后，各寄存器等待下一次本域时钟沿恢复工作。实际系统若复位源本身异步于该时钟，应在外部为每个域添加「异步断言、同步释放」的复位同步器，避免释放边沿落入触发器的恢复/移除时间窗口。不能把格雷码两级同步器当作复位释放电路，因为它们的数据输入是另一域指针，不是复位信号。

初始化时通常让两侧复位都有效，再分别安全释放。`tb_reset_skew` 展示了写侧先释放的情况：读域仍复位时，其 `rempty` 保持 1，即便写域已把 `0xA5` 写进存储；读域释放并同步到写指针后，数据仍能读出。这证明复位会把标志保持在已知状态，不证明运行中任意单侧复位都能保持队列事务语义。运行中清一侧可能需要上层丢弃整批数据并重新对齐，必须另行设计。

## 八、存储体写法与 BRAM 推断

存储声明没有复位：

```verilog
reg [DATA_WIDTH-1:0] mem [0:DEPTH-1];
```

写入在写时钟沿完成，读出为异步组合读：

```verilog
assign rdata = mem[rbin[ADDR_WIDTH-1:0]];
```

这是理解资源结果的关键。许多 FPGA 的块状 RAM（BRAM）支持双时钟写入/读取，但读端口通常是同步读，至少地址会进入寄存器；当前模型要求读地址不经读时钟寄存就直接产生 `rdata`。因此综合器往往只能把它映射成寄存器或分布式存储加读多路选择器，而不能直接推断为最典型的同步读 BRAM。

「没有复位」有利于存储推断，但并不足以保证 BRAM；**读时序结构同样决定能否映射**。如果产品希望使用 BRAM，应把读接口改成目标器件支持的同步读形式，重新核对 `rempty`、`rinc` 和首数据可见时序，或者直接使用厂商双时钟 FIFO IP。不能只加一个 RAM 风格属性就假设协议还保持原样。

深度增大时，组合读多路选择器和地址译码也会增长，这会影响面积与拓扑路径。第四篇的通用综合数据正好展示了这种趋势，但通用单元数不是某款 FPGA 的最终 LUT/FF/BRAM 数量。

## 九、把完整数据流串起来

一次写入到读出的逻辑链路如下：

```text
wclk 域                                      rclk 域
--------                                     --------
wdata → mem[写地址]                          rdata ← mem[读地址]
winc  → wbin_next → wbin                     rbin ← rbin_next ← rinc
           │          │                            │
           └→ wgray_next → wgray                  └→ rgray
                              │                        │
                    两级同步到 rclk              两级同步到 wclk
                              │                        │
                    wgray_rsync2 → 空比较       rgray_wsync2 → 满比较
                              │                        │
                           rempty                     wfull
```

`mem` 是两侧共享的存储体，但控制状态严格分侧。写侧不直接读 `rbin`，读侧也不直接读 `wbin`；跨域的只有格雷码指针，而且各自经过目的域两级同步。

检查任何修改时，可以连续追问四个问题：跨域的是不是只有 Gray？Gray 是否只在源指针每次递增时变一位？满空是否只使用第二级同步值？读写准入是否与指针推进使用同一条件？任何一个答案变成「否」，都需要重新证明安全性，而不是只跑一遍正常流量。
